# Support

GeoAI Skills is maintained as an open-source project. Use the channel that
matches the problem so public questions remain searchable and sensitive reports
remain private.

## Public questions and reports

Open a GitHub issue for:

- installation or clean-install failures;
- a skill that activated when it should not, or failed to activate;
- a methodological guardrail that is wrong, incomplete, or too broad;
- a reproducible real-world failure case;
- a benchmark, documentation, or portability defect; or
- a proposal for an independently authored evaluation case.

Include the runtime and version, model identifier as reported by the runtime,
operating system, install command, relevant skill, smallest privacy-safe prompt
or reproducer, expected behavior, observed behavior, and logs with credentials
removed.

## Security and sensitive locations

Do not open a public issue for secrets, prompt-injection paths, unsafe command
execution, private datasets, or identifiable location traces. Follow
[SECURITY.md](SECURITY.md) and use GitHub private vulnerability reporting.

## Evidence corrections

If a published number cannot be recomputed, open an issue naming the evidence
package and file. A correction must preserve the original record, explain the
cause, and mark superseded evidence explicitly. Routing, behavior, external
transfer, and real-world evidence are never pooled to make a stronger number.

## Response expectations

There is no guaranteed service-level agreement. Security reports target an
acknowledgement within seven days as stated in [SECURITY.md](SECURITY.md).
Public issues are prioritized by correctness and safety impact, then
reproducibility, then feature demand.
